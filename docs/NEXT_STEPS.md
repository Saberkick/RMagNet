# RMagNet 下一步实施路线

> 2026-09-18。以“界面识别 + T/R 分离训练 + 最终融合”为现阶段目标。以下是计划，不表示这些步骤已完成。

## 最先做什么

**第一项工程工作是接通真实共享 DiT 底座，并证明新代码在关闭新模块时能够复现已保存的 WindowSeat 输出。** 若这一步不成立，后续训练结果无法判断来自新架构，还是来自 VAE 归一化、token 打包、单步 flow 符号或裁块流程的实现差异。数据盘中已有固定的 WindowSeat 仓库、uv 环境和模型快照；复用它们，不重新下载权重。

## 里程碑与验收闸门

| 顺序 | 交付物 | 必须通过的检查 | 依赖 |
| --- | --- | --- | --- |
| **M1 真实后端** | `QwenSharedBackend`：同一底座分别调用 T/R adapter，单步 VAE→DiT→VAE | 先关闭新增 adapter/融合，与固定 WindowSeat 的 11、12、17 输出在相同预处理/seed 下做数值对齐；再用伪 T/R adapter 验证切换与训练参数集合 | 已有代码、权重、环境 |
| **M2 数据规范** | 真实 manifest、帧配准/曝光审计、场景 split、质量报告 | 每对 RGB/GT 和四偏振帧可追溯；场景不跨 split；记录不可靠区域；不以三张开发图估计泛化 | 更多自采数据与角度/GT 元数据 |
| **M3 界面层** | 合成界面和编辑 mask 标签、真实偏振弱标签、界面模型 | 分别报告界面/编辑 mask 的准确性；在高 DoLP 负例上不过度擦除 | M2，合成数据 |
| **M4 分支训练** | `LoRA_T`、`LoRA_R` 与可重启的单支训练入口 | T 在配对 GT 上改善；R 在合成真 R 上有独立预测能力；冻结底座、梯度与显存检查通过 | M1、M2，合成 R 真值 |
| **M5 融合训练** | 读取两路候选、原图、mask 的小融合器；交替微调 | 删除/随机置换 R 会有可解释的性能变化；文字和无反射区域的误改下降；两路图与显存可控 | M3、M4 |
| **M6 对比评估** | 固定评测配置、逐图 CSV、区域指标、失败案例图和训练/推理成本 | 相同输入尺寸、保存后 8-bit PNG 口径与 WindowSeat/RDNet 比较；在独立新场景测试集报告结论 | M5、足够的留出场景 |

M1 与 M2 可并行准备，但**M1 的数值对齐、M2 的数据质量**都通过后才应解释正式训练结果。官方 WindowSeat 仓库目前主要提供推理与评测代码，RMagNet 的反向训练循环需要单独实现。[WindowSeat 仓库](https://github.com/huawei-bayerlab/windowseat-reflection-removal)

## M1 的具体工作包

1. 固定当前本机 WindowSeat 提交、模型 revision、环境版本和三图输入哈希，记录 baseline PNG 与逐图指标。
2. 将官方推理拆成可微的 `encode → flow_step → decode`，接入 `AdapterRoutedBackend`；保留固定文本 embedding、VAE 归一化、timestep 和 tile 拼接的一致性。先只跑 T 路且不训练。
3. 使用同一个已加载的底座注册两个**命名** LoRA；分别激活并输出候选。真实 PEFT `set_adapter` 可能改变可训练参数集合，逐支检查 `requires_grad`、optimizer 参数以及反向梯度。两个 LoRA 在一次前向中同时激活不是这个实验。
4. 在一张合成小图上分别做 T/R 单支 forward/backward，记录 512 与 768 候选 crop、batch 1 的峰值显存、每步时间和磁盘增量。若一个分支都不能稳定训练，先缩减 LoRA 插入层/rank、使用梯度检查点，再决定是否分片；**不直接启动双支联合训练**。

M1 的交付可以是推理一致的 backend 和实测表，尚不需要证明质量提升。初始化策略：T 路可用已训练的 WindowSeat LoRA 作基线，再决定冻结、继续训练或增加低秩增量；R 路需要独立的反射目标。不要把同一个 T LoRA 复制一份就当成“已经分离”。

## 数据与标签如何进入训练

每个记录至少包含 `scene_id`、`capture_id`、输入、GT、四帧路径和偏振角度、曝光/白平衡、配准分数、split。未确认偏振角度的照片不能直接按标准 0/45/90/135 Stokes 公式处理。GT 用最少反射帧时，保留残余反射和细节遮蔽的审计标志。

先获得一批可审查的合成 PBR 样本：输入、真实 clean T、真实 R 或反射渲染通道、界面 mask、编辑 mask 同时保存。界面头主要用这些强标签起步；真实 DoLP 只作为软提示和采样权重。R 的真实照片残差只在配准、线性化、未饱和区域作弱约束。训练/验证/测试按拍摄场景分组，同一场景的四帧和连拍不得分散。

## 显存、存储与实验记录

服务器是共享的 24 GB RTX 3090；上次检查时存在空闲 GPU，但正式训练前需重新查询。两次分支前向共享底座**只节省参数存储**；若融合损失同时反传到两个 LoRA，自动求导仍会保留两条计算图。首轮策略是分别训练、冻结候选训练融合、交替微调。若要同步联合反传，先做峰值显存实验。

软件由 uv 管理，缓存、临时文件、数据、checkpoint 和日志均放 `/share/linmingheng-local/xuke`。复用现有 Qwen/WindowSeat 模型快照；只保存 RMagNet 适配器、界面/融合器及必要优化器状态，避免复制基础权重。每次实验记录代码提交、配置、模型 revision、数据 split 哈希、随机种子、显存、耗时、逐图指标和失败案例。

## 成功标准与停顿条件

- **架构可训练**：真实 backend 数值对齐；T/R adapter 分开生效且获得预期梯度；单支训练 loss 可下降、无 NaN/OOM。
- **分离确有作用**：R 分支在合成真值上有意义；去掉或置乱 R 时，融合结果发生符合预期的退化，而非完全不变。
- **保真优于基线**：不仅比较 PSNR/SSIM，还要看无反射区误改、字形/细线和凭空增删物体。11、12、17 固定用于回归；最终结论用独立新场景。
- **暂停增加复杂度**：若 M1 无法复现既有推理，先修实现；若 M2 的 GT/配准不可靠，先修数据；若 R 被融合器忽略，先修监督和融合，不继续加第三个 DiT LoRA。

### 当前最具体的下一步

实现并验证 **M1：真实 Qwen/WindowSeat 共享底座适配器后端**，产出数值对齐报告与单支训练显存表。同时整理可用于 M2 的真实四偏振数据目录和元数据；未完成 M1/M2 前，不启动正式 T/R 训练。
