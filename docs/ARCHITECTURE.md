# 架构与张量契约

> 当前采用 M1a 三 LoRA 方案。完整决策见 [M1a 最终方案](M1A_DESIGN.md)；下文的小型像素融合器是早期可运行基线，保留用于消融，不再是最终主线。

## 当前主创新

输入 RGB `I`。界面层分别输出 `M_interface`（可能的反射界面）、`M_edit`（本图需要去除的干扰）、`C_keep`（保留输入像素的信心）。共享 DiT 底座依次激活 `LoRA_T` 与 `LoRA_R` 做**两次前向**，得到透射候选和反射候选。融合器读取两个候选、三张图和原始 RGB，输出 `T_final` 与不确定性。

```text
I ─► interface head ───────────────┐
│                                  │
└─► frozen shared DiT + LoRA_T ─► T │
 └► frozen shared DiT + LoRA_R ─► R ├─► small fusion ─► T_final, U
I ─────────────────────────────────┘
```

两个 LoRA 同时叠加在一次前向里不会自动生成 T/R 两个结果。`AdapterRoutedBackend` 预留了在一个 Transformer 对象中逐次切换 adapter 的接口；真正的 Qwen VAE 编解码、latent 打包和一步 flow 更新尚待接入。融合器使用小网络，避免第三次完整 DiT 前向。

适配器切换本身只验证了**两次有区别的前向**。真实 PEFT/DiT 联合训练还要检查 `set_adapter` 对各 LoRA 的 `requires_grad` 影响，不能仅凭玩具网络的梯度结果宣称两路能同时端到端反传。首轮真实训练按文档所述分别训练、冻结融合、再交替微调。

## 形状和范围

所有张量采用 `B,C,H,W`。输入与候选为 `[0,1]` 的 RGB。三张界面图和不确定性为 `[0,1]` 的单通道。`M_interface` 与 `M_edit` 独立预测；玻璃界面并不意味着该处当前一定要改动。玩具底座在 `32×32` 的随机张量上检查契约；真实模型必须另验证 512/768 crop 和原分辨率 tile 的尺寸关系。

融合初始形式为 `T_final = clamp(I + M_edit · (T_candidate - I + delta), 0, 1)`；`delta` 从零初始化。R 候选进入融合器，但只有对照消融能证明它没有被忽略。强反射区缺少可观测纹理时，输出不确定性，不能把生成内容当成已证实的现场事实。

## 监督和可辨识性

- 合成 PBR：保存 clean T、真实 R 或反射渲染通道、界面与编辑 mask，分别监督两条 LoRA 与界面层；在可靠线性空间验证重合成。
- 真实偏振：配准后的最少反射帧监督 T；四帧偏振响应给界面层弱提示。`I-T*` 仅是受曝光、相机响应、错位影响的弱残差，不能当真实 R。
- 融合：监督最终 T、无反射区的输入保持；用删除 R、删除 mask、替换 R 的实验检查各模块贡献。

同一场景的四偏振帧及连拍不能跨训练与测试集合。当前 11、12、17 只做回归检查，不做最终泛化结论。
